## Product decision

Own the customer record, inquiry funnel, human handoff, execution receipts and recovery in Frappe. Use the existing database, queues, Chatflow and review queues. Meta, WhatsApp, telephony, AI, n8n and vertical applications are optional adapters. A disconnected provider must leave core work usable and pending work visible. No universal workflow designer or new infrastructure is required to complete these paths.

Reliability means preventing duplicate effects, preserving evidence, exposing uncertainty and recovering safely. It cannot mean that an external provider never fails. A green connection is also not proof of coverage: subscription, permission, received event, enrichment and conversion are separate checkpoints.

### Dependency and scope rules

ACQ-01 is independent of marketing and bots. ACQ-02/03 are optional marketing additions. AUTO-01/03 precede autonomous recipes; do not switch bots on from an installation flag. VERT-01 precedes write integration. VERT-02 precedes appointment actions involving an identified patient. EXT-02 precedes an n8n recipe. REL-01 gates publication of every completed package, rather than waiting for one risky giant release.

Reuse upstream Forms already selected and tested. Record upstream provenance and adapt tests; do not merge the entire divergent upstream branch. New funnel work must reuse the native Lead/Deal model and native Forms rather than duplicate them.

## First implementation contract: native inquiries

CRM owns `CRM Inquiry` and child `CRM Inquiry Person`. A source conversation is not itself a verified person. Fields and API are shared by the frontend and backend assignments below.

Parent: `title`, `status` (New/In Progress/Closed), `source_type` (Manual/Facebook/Instagram/Other), `source_url`, `source_text`, `capture_key` (unique SHA-256), hidden immutable `capture_payload_hash` (SHA-256), `assigned_to` (User), `next_action_at` (Datetime), `people` (child table), plus Frappe owner/creation/modified. Keep text plain, bounded; permit only http/https source links; never fetch user URLs. No private screenshot upload in this package: existing private File handling needs a dedicated permission test before enabling it.

Child: `person_key` (stable server-generated token), `display_name`, `role` (Requester/Referrer/Interested Person), `email`, `phone`, `lead` (CRM Lead, read-only), `converted_at` (read-only). Display names/aliases are labels, never verified channel addresses. A referrer is not convertible; explicitly add or classify a distinct interested person. Never search/merge leads automatically using an alias or phone.

Public POST API module `crm.api.inquiries`:

- `create_inquiry(payload)`: {title, source_type, source_url, source_text, client_request_id, people:[{display_name,role,email?,phone?}]}. Default assignment current actor. Reject unknown keys/oversized payloads; normalize only documented input. Scope replay key to current actor + request id; reject changed payload replay. Return serialized inquiry.
- `list_inquiries(status?, assigned_to?, start=0, page_length=20)`: {items:[parent summaries],has_more}. Permission-filtered pagination, newest modified first. No children or source text in list.
- `get_inquiry(name)`: serialized parent + people, direct permission check.
- `update_inquiry(name, modified, values)`: optimistic concurrency; only title/status/assigned_to/next_action_at. Closed inquiries remain readable and can reopen explicitly. Eligible assignees require enabled CRM role; assignment cannot disclose records to a non-CRM user. A successful transfer that revokes the actor’s read access returns only {name,access_revoked:true}; the client immediately clears protected detail.
- `add_person(name, modified, person)`: adds one explicitly classified person; serialized response.
- `convert_person(name, person_key, existing_lead=None)`: locks and rereads source; check inquiry write + CRM Lead create (or target write for link). Create only selected Requester/Interested Person. Repeated conversion returns existing authorized lead. Source label and source URL retained on inquiry; no new contact/patient or outbound message. Return {inquiry:<serialized>,lead:<name>,created:<bool>}. Child's linked lead cannot be forged via generic save or altered after conversion.
- `get_assignees()`: bounded list of enabled System Manager/Sales Manager/Sales User identities permitted for assignment, no full User document exposure.

Permissions: System Manager/Sales Manager can triage all; Sales User only own or assigned. Both permission query and document checks enforce this, including generic REST/Desk access. No guest endpoints. API uses normal document/lead permissions; no externally callable ignore-permissions switch. Record provenance, child keys and conversion results immutable through generic writes. No commit inside service functions; successful POST transaction commits normally. After-commit realtime is user-targeted and content-free. Assignment writes an internal CRM Notification with generic text; its inquiry route works and notification retrieval rechecks current inquiry access. Parent/current-owner permission checks use a locking read. Linked leads are additionally protected at field permission level 1, redacted from generic responses and sanitized error messages when denied; the dedicated API exposes them only after a current target permission check.

Adapter boundary: marketing provides `doco_marketing.services.social.referrals.capture_mention(name)`. It rechecks branch/source access, requires CRM installed/schema ready, then invokes the **internal, non-whitelisted** `capture_source_inquiry(source_key,payload)`. The adapter hashes `[mention_type, stored provider source_key]` in a marketing namespace; identity survives Desk rename, branch reassignment and duplicate source rows. Existing nonempty source identity is immutable through generic saves. Missing/invalid identity requires explicit manual capture, never a guessed fallback. CRM uses a separate hash namespace from manual actor/request IDs and enforces normal insertion/read permissions. Authorized staff replay the original inquiry snapshot, ignoring later provider enrichment; denied staff get no duplicate or content. Source author is a **Referrer**, not an automatically selected buyer. Capture remains an explicit staff action.

Conversion boundary: creating a new inquiry lead scopes `frappe.flags.crm_inquiry_capture` to that insertion, with guaranteed restoration. Updated marketing campaign enrollment honors the flag for lead-created and score-crossed hooks. If marketing is installed without the compatibility marker, CRM retains the inquiry and requires the matching marketing upgrade before new-lead creation; explicit existing-lead linking remains available. This prevents capture from implicitly enrolling an alias into campaigns. No global suppression change or transaction commit is introduced.

Frontend: core `/inquiries` route with navigation for desktop/mobile, manual capture form and list/detail view; identify people and roles; add selected person; create or explicitly link an existing lead; assign/next action/close/reopen; busy state, field validation, permission/connection/concurrency errors and retry preserving user draft. Social Menciones exposes “Capturar consulta” linking to the resulting inquiry; generic acquisition path always accessible even when marketing unavailable. Avoid raw HTML rendering of source text. No promise that every social mention automatically arrives.

## Builder decision protocol

Fable receives only assigned source files and this contract; no credentials, backups or customer records. It may read/edit source and write tests, never deploy, migrate, message customers or access provider accounts. Separate backend/frontend ownership. Codex runs commands and audits outputs.

Builders write `coordination/inquiries/{backend,frontend}/STATUS.md`, `QUESTIONS.md`, `RESULT.md`; Codex owns shared `DECISIONS.md`. Read decisions before final result. Escalate only identity/consent, schema/backfill, external effects, incompatible API changes or blockers. Routine choices use this contract. File checkpoints do not guarantee instant delivery: Codex starts a follow-up when a material decision was missed.

## Next bounded assignments

Each assignment includes code, meaningful fault tests, compatibility/rollback notes and an audit. No task is complete merely because a schema or a button exists.

1. **ACQ-04 ingestion reliability:** inventory `mentions._upsert`, webhook dispatch and tagged backfill. Replace exists-check/whole-transaction commit/rollback with a unique receipt and request-local savepoint. Backfill a provider/account/event identity; quarantine unresolved historical collisions instead of deleting rows. Resolve credentials for the receiving account. Persist delivery/enrichment evidence before remote work, retry only enrichment, and test duplicate/out-of-order events, deleted/edited events, tenant isolation and unavailable Meta content. Reuse the internal inquiry source receipt for explicit opted-in routing. Review the additive migration and collision report before running it.
2. **AUTO-01 + AUTO-03 safety core:** map every existing Chatflow/cadence/review/broadcast send into one durable intent lifecycle. Establish bot/human/paused/closed ownership and optimistic generation before activating any native bot. Commit intent with its local domain action; enqueue after commit. Claim with a bounded lease. A post-submission crash is Unknown until provider evidence or authorized review resolves it. Do not infer safe retry from a timeout or expired lease. Prove two workers, human takeover, consent revocation and crash at each boundary with fake transports.
3. **AUTO-02 + AUTO-04 usable execution:** immutable published flow revision, pinned run snapshot, explicit wait/cancel/step budget and allowlisted local actions. Expose a run timeline, owner, committed denial and permitted recovery action in API, CRM and Desk. Draft-first recipes qualify/assign/prepare a reply/hand off. Kill switch prevents new submissions; it cannot undo a message already accepted by a provider.
4. **VERT-01 then VERT-02/03:** provisioning owners are Boat/Muelle/Abordo; Clínica owns idempotent preset seeding and all domain writes. Use the fresh wiring document’s intake, agenda and reminder services. Test a fictional health signup and replay preserving admin edits before implementing explicit patient/guardian/payer relationship and conversion receipts. Appointment actions require current clinical authority and resource/version checks. Neither CRM role nor shared phone grants clinical access.
5. **EXT-01/02 + UX-01:** show last stored, last received and last verified evidence separately; provide bounded operator repair. Add signed, idempotent adapter contracts before n8n recipes. Secret rotation/replay protection and recipient/purpose authorization are mandatory. Funnel counts use persisted inquiry/person/lead/deal/conversion facts. Surface overdue owned inquiries and missed follow-ups without creating duplicate tasks or notifications on page reload.
6. **REL-01:** complete the published matrix per journey, not an enormous Cartesian test suite without meaning. Fresh core install, compatible upgrade, each supported vertical and each optional-provider failure mode get explicit acceptance. Protect rollback data, inspect full guarded migration output, validate served assets and perform a canary smoke before exposing a feature. Inquiry privacy requires the matching controller/permission hooks and refreshed caches on every worker; rollback must retain that security bundle or keep the site unavailable while restoring a compatible backup, never expose new tables under old permissive hooks. Use measured pilot evidence to set SLOs; no zero-outage promise.
