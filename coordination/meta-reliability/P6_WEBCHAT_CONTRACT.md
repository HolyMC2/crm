# P6 Webchat visitor contract — 2026-09-10

Webchat is a finite provider over existing CRM Conversation/control/outbox. The visitor broker owns only Channel, Session and immutable Message storage; it never calls a staff broker, changes the current user, creates a person/Inquiry/Lead, grants consent, runs an assistant/model, sends HTTP, enqueues work or commits/rolls back. Root owns the existing core provider/permission/thread/outbox integration and storefront BFF/widget.

## Additive schema (approved; root owns installation)

- **CRM Webchat Channel:** name/account_id random 64hex, immutable unique binding_key=SHA256(canonical `[profile,public_origin]`), label, exact Storefront Profile name as Data `profile`, canonical HTTPS `public_origin`, enabled default0. One saved binding even while disabled; profile/origin/account identity never reassign. System Manager read/report; mutation only with the private service object token.
- **CRM Webchat Session:** independent random64hex name and unique random64hex peer_id, channel Link, unique SHA256 capability_hash (hidden), expires_at exactly24 elapsed UTC hours from Frappe-assigned creation (stored in site local time), revoked default0. No names, addresses, phone numbers, CRM person or staff session linkage. The only allowed update is irreversible revoke; expiry/capability/identity stay fixed.
- **CRM Webchat Message:** name/message_key stable64hex, channel/session/conversation Links, indexed peer_id, Incoming/Outgoing direction, bounded request_id, text as Code/Text to preserve exact plain text without HTML sanitizer rewrites, text_hash and immutable control_generation. Transcript is append-only. Session/Message have zero generic permissions and fixed deny-all read/query hooks registered by root, including Administrator via controller guards as well as list query hooks. Generic private-record notifications are disabled; only scoped broker events remain.

## Endpoints

All visitor endpoints below accept **POST application/json only**, at most16 KiB raw JSON, no duplicate/nonfinite JSON and no URL query arguments. Body keys must match the finite signature; no caller peer, conversation, reference, actor, origin/IP authorization, body capability or token-in-URL. Responses set actual Frappe response headers `Cache-Control: private, no-store` and `Pragma: no-cache`, including validation failures.

| Method (`crm.api.webchat.` prefix) | Arguments | Safe result |
| --- | --- | --- |
| `get_channel` | `profile`, `public_origin` | `{available:false}` or `{available:true,channel_id,label}` for exact normalized enabled binding. These are public routing keys, not transcript authority. |
| `bootstrap` | `channel_id` | `{capability,expires_at}` with explicit UTC ISO8601 `Z` expiry. Random256-bit URL-safe capability is returned once; only its SHA256 is stored. Session only, no conversation yet. |
| `send` | `channel_id`, `request_id`, `text` | Own bounded transcript, `message`, `replayed`, `control_state`, `next_cursor`. Text1–2000 characters, preserved literally; no C0 controls except tab/newline/carriage return. |
| `history` | `channel_id`, optional `cursor` | At most50 own messages, `next_cursor`, `control_state`. Cursor is an opaque immutable message key, checked against exact channel/session/peer; ordering uses creation+name. Newest page is returned chronologically. |
| `revoke` | `channel_id` | `{revoked:true}`. Repeated own revoke is harmless; no transcript deletion. |

For history/send/revoke the BFF sends `Authorization: Bearer <43-character capability>`; no staff Cookie or other authentication. `prepare_request` is a fixed root-registered before-request hook for exact `/api/method/crm.api.webchat.{method}` and `/api/v1/method/...` paths. It removes Authorization before Frappe OAuth/API authentication and stores only a hash in an opaque exact-request context; it never changes the Guest principal. get_channel/bootstrap accept no Authorization. Missing/stale authority is denied. Static HTTP error JSON `{message,reason}` uses403 session_unavailable,417 request_invalid,429 rate_limited and503 temporarily_unavailable; unexpected exception details never enter the public response.

Every message projection has only `{id,text,direction,created_at}`, with created_at also explicit UTC ISO8601 `Z`. Control projection is only the finite state, with null before the first conversation exists. No staff actor IDs, owner, generation, references, notes, clinical records, raw payloads, capabilities or token hashes are projected (bootstrap's once-issued capability is the sole exception).

Manager-only POST `configure_channel(label,profile,public_origin,enabled=0,channel_id=None,expected_modified=None)` validates current enabled User/current SQL System Manager role. Existing records require the exact modified revision and immutable binding. Creation never adopts an existing binding without its saved identity/revision. Returns only `{account_id,label,profile,public_origin,enabled,modified}`. Manager-only POST `list_channels()` returns `{channels:[safe config projections],has_more:boolean}`, at most100 saved rows sorted by label/name. Root owns its Desk operator path.

## Authority, rate and transaction boundaries

Authentication first resolves private header-authority capability hash to a nonlocking scope hint. It then takes the existing core conversation fence, locks current Channel and Session, and rechecks exact identity, hash, enabled state, expiry and revoke. This lock order matches outbound dispatch. Possession of a valid capability grants only its own transcript. No visitor cookie, analytics identifier, provided IP/origin or staff session is used as identity authority.

Fail-closed atomic Redis counters use `frappe.cache` site-prefixed keys and hashed identities. Actual WSGI `request.remote_addr` is used, never a supplied IP or forwarded header: 6000 requests/minute per observed shared egress IP, 600/minute per channel; bootstrap additionally3000/hour/shared egress IP and300/hour/channel; own session90/minute, new send/replay30/minute/session. These are shared infrastructure and channel budgets, not per-visitor identities or a scale guarantee. The BFF/proxy may aggregate visitors under one observed IP. Redis failure, malformed counter or exceeded quota fails before visitor persistence. Counters expire atomically on first increment and contain no capability or raw IP. The storefront also owns its independent host/IP/CSRF limits.

Incoming identity is SHA256(canonical `[1,channel,peer,'Incoming',request_id]`). Identical frozen text replay returns the first row before any control helper. Changed text for an existing key is rejected. A new message calls existing `get_or_create('Webchat',channel,peer)` under the same fence, with no reference; Human/off/unowned is the default. Closed refuses new messages while allowing prior identical replay; Paused remains Paused. The first insert records current control_generation and calls root `internal_webchat_customer_reply(conversation_name,message_key)` in the same transaction. That helper validates the actual stored message/session/channel and may retire only the matching Bot generation. No Meta receipt or timestamp is fabricated.

Internal `current_session(channel_id,peer_id)` returns the exact current live locked Session document, including `.name`, for core eligibility. `validate_payload(payload,*,account_id,peer_id)` is pure and returns canonical bytes for exactly `{'type':'text','text':body}`. `deliver_local(intent,payload)` calls root `outbox.require_dispatch` **first**, verifies exact frozen body/provider/account/peer, and inserts one immutable Outgoing message with request_id=intent.name. Its stable result is `{'state':'Accepted','provider_message_id':'webchat.'+message_key}`. Root's local outbox path commits that row and Accepted state atomically; this module owns no transaction boundary or worker.

Root completed the approved inert schema/controller commit and guarded lab migrations. Runtime remains uncommitted pending package review.

New Incoming/Outgoing messages emit `crm_conversation_updated` with only `{name: conversation_id}` and `after_commit=True` to the exact currently authorized human owner and (Outgoing) intent actor. Replays emit no message hint. Unowned queues retain bounded authorized polling; there is no account/global broadcast.

Installed Frappe parses JSON before application hooks. The header protocol keeps legitimate capabilities out of malformed-body snapshots. Tests inspect real malformed-JSON traceback/metadata and Sentry WSGI header filtering. Endpoint errors are static HTTPException responses, with request body/JSON/form diagnostic caches scrubbed. The optional Administrator Recorder runs earlier: the finite hook scrubs its captured header/form metadata, runs actual cleanup, clears captured calls/events and disables recording only for this request. Actual Recorder.dump then persists nothing. If exclusion fails the request refuses503; no global debug configuration changes are made. No claim is made against privileged memory inspection, custom infrastructure logging, or credentials deliberately placed in unsupported body/query fields.

Deployment must invalidate the exact site app_hooks cache when publishing these hooks. Both isolated sites retained pre-Webchat app_hooks despite the schema migration; root-authorized deletion of only that key restored before_request and generic-list privacy outside developer mode.
