# Native manual outbox acceptance — 2026-09-10

The first native send path stores an immutable intent before queueing a plain-text WhatsApp reply. Only the current human owner can create it. The provider account, peer, conversation generation, initiating user, complete vendor body and account/App/business revision are fixed. Repeating the same browser request ID returns the existing intent; changed content or generation under that ID is rejected. No request, callback or generic document flag can fabricate the private dispatcher capability.

The worker acquires the same MariaDB conversation fence as human control commands. It clears its read-only routing snapshot after waiting, commits a bounded claim, rechecks current authorization and eligibility, then commits Submitting before the single provider attempt. The gateway's first operation checks the exact current intent, claim token, frozen bytes and scope again. The fence remains held through every commit and the HTTP result. Account/shop/user/role/reference revocation, private staff assistant peers, changed generation, changed App/business configuration, explicit suppression, maintenance, expiration and an unverified customer window prevent sending.

The 24-hour window uses authenticated Processed receipt evidence and the actual provider timestamp, exact App/account/peer and message event type. Received-at and newly created WhatsApp Message timestamps cannot reopen it. A nonlocking candidate lookup is followed by primary-key locking revalidation; a broad locking JSON scan would block unrelated receipt admission while HTTP runs. Explicit opt-out is still enforced for a service reply; newsletter confirmation does not grant or deny that manual service purpose. There is no consent grant or identity merge in this path.

Accepted requires a valid exact-recipient provider response with a real-shaped message ID. Timeouts, broken connections, 5xx, redirects, malformed or ambiguous responses and an expired Submitting lease become Unknown. Unknown has no retry/cancel path. An expired claim before Submitting can be reclaimed; a definitive rejection without a provider ID can be explicitly retried under the original authority, up to three claims. Accepted/Delivered/Read are never queued again. Cancellation and retry preserve the intent identity and append protected state history. A minute scheduler sweep recovers committed but unenqueued work. Worker methods reject HTTP and receipt-worker invocation; public create/cancel/retry methods never commit internally.

Private scope enforcement is shared with the new customer thread broker. Current Doco WhatsApp principal/history keys have no account dimension, so an exact known private peer is conservatively excluded across accounts, including disabled historical principals. Only identity existence is consulted; private transcripts, clinical content, attachment bodies and assistant resolver side effects are not read. Ownership requests now notify the currently authorized owner using only conversation ID/generation after commit.
